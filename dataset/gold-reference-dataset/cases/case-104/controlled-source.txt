# Lab result release authorization requirements

Case: case-104
Domain: lab_result_release
Selected actions: acknowledgeCritical, releaseResult, releaseToPortal

## Purpose

Determine whether a user may perform each of these operations: acknowledge a critical lab result; release a lab result; release a lab result to the patient portal.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to release a lab result
Action: releaseResult
Requester type: User.
Resource type: LabResult.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [at least one of [the user has the "Pathologist" role; the user has the "OrderingProvider" role]; all of [all of [the request's emergency release flag [context.emergencyRelease] is true; the user has the "MedicalTechnologist" role]; the user [principal] equals the lab result's verifier [resource.verifiedBy]]].
- Access requires that the lab result's sensitivity [resource.sensitivity] is one of [0; 1; 2].
- Unless all of [all of [the request's emergency release flag [context.emergencyRelease] is true; the user has the "MedicalTechnologist" role]; the user [principal] equals the lab result's verifier [resource.verifiedBy]], access requires that the user [principal] differs from the lab result's verifier [resource.verifiedBy].
- If the lab result's critical flag flag [resource.criticalFlag] is true, access requires that the critical release review has been completed [context.criticalReleaseReviewCompleted].

## Permission to release a lab result to the patient portal
Action: releaseToPortal
Requester type: User.
Resource type: LabResult.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "Pathologist" role; the user has the "LabDirector" role].
- Access requires that the user's credential level [principal.credentialLevel] is one of [0; 1; 2].
- Access requires that the lab result's sensitivity [resource.sensitivity] is one of [0; 1; 2].
- Access requires that the lab result's status [resource.status] equals the "released" status [LabResultStatusValue].
