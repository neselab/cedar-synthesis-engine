# Network change approval authorization requirements

Case: case-286
Domain: network_change_approval
Selected actions: approveChange, implementChange

## Purpose

Determine whether a user may perform each of these operations: approve a network change; implement a network change.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to approve a network change
Action: approveChange
Requester type: User.
Resource type: ChangeRequest.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "ChangeManager" role; the user has the "CABApprover" role].
- Access requires that the user's authority level [principal.authorityLevel] is one of [0; 1; 2; 3].
- Access requires that the change request's affected node count [resource.affectedNodeCount] is at least 0.
- Access requires that the change request's change risk [resource.changeRisk] is one of [0; 1; 2; 3].
- Access requires that the change request's estimated cost [resource.estimatedCost] is at least 0 USD cents.
- Access requires that the change request's rollback step count [resource.rollbackStepCount] is at least 0.
- Access requires that the user's authority level [principal.authorityLevel] is at least the change request's change risk [resource.changeRisk].
- If the sum of [the change request's affected node count [resource.affectedNodeCount]; the change request's rollback step count [resource.rollbackStepCount]] exceeds 10, access requires that the host confirms completion of the additional review [context.approveChangeV7ReviewCompleted].
- If the change request's estimated cost [resource.estimatedCost] exceeds 1,000,000 USD cents, access requires that the user has the "CABApprover" role.

## Permission to implement a network change
Action: implementChange
Requester type: User.
Resource type: ChangeRequest.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "NetworkEngineer" role; the user has the "SeniorEngineer" role].
- Access requires that the change request's affected node count [resource.affectedNodeCount] is at least 0.
- Access requires that the change request's status [resource.status] equals the "approved" status [ChangeRequestStatusValue].
- Unless the change request's emergency change flag [resource.emergencyChange] is true, access requires that all of [the elapsed milliseconds difference of [the request's current time [context.currentTime]; the change request's maintenance window start [resource.maintenanceWindowStart]] is at least 0; the elapsed milliseconds difference of [the request's current time [context.currentTime]; the change request's maintenance window start [resource.maintenanceWindowStart]] is less than 14,400,000].
