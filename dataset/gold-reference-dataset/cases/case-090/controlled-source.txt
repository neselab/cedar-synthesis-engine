# Claim adjudication authorization requirements

Case: case-090
Domain: claim_adjudication
Selected actions: approveClaim, issuePayout

## Purpose

Determine whether a user may perform each of these operations: approve a claim; issue a payout.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to approve a claim
Action: approveClaim
Requester type: User.
Resource type: Claim.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "Reviewer" role; the user has the "ClaimsManager" role].
- Access requires that the claim amount [resource.claimAmount] is at least 0 USD cents.
- Access requires that the claim's deductible [resource.deductible] is at least 0 USD cents.
- Access requires that the claim's line item count [resource.lineItemCount] is at least 0.
- Unless all of [the catastrophe has been declared [context.catastropheDeclared]; the user has the "ClaimsManager" role], access requires that the user [principal] differs from the claim's handler [resource.handler].
- Access requires that the claim code [resource.claimCode] matches the Cedar wildcard pattern "AUTO-*".

## Permission to issue a payout
Action: issuePayout
Requester type: User.
Resource type: Payout.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "PayoutOfficer" role; the user has the "ClaimsManager" role].
- Access requires that the payout's amount [resource.amount] is at least 0 USD cents.
- Access requires that the payout's claim / claim amount [resource.claim.claimAmount] is at least 0 USD cents.
- Access requires that the payout's claim / deductible [resource.claim.deductible] is at least 0 USD cents.
- Access requires that the payout's claim / line item count [resource.claim.lineItemCount] is at least 0.
- Access requires that the payout's claim / status [resource.claim.status] equals the "approved" status [ClaimStatusValue].
- Access requires that the payout's claim / claim code [resource.claim.claimCode] matches the Cedar wildcard pattern "LIABILITY-*".
- Access requires that the payout's amount [resource.amount] equals the difference of [the payout's claim / claim amount [resource.claim.claimAmount]; the payout's claim / deductible [resource.claim.deductible]].
