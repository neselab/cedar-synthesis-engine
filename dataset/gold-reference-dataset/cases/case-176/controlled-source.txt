# Expense reimbursement authorization requirements

Case: case-176
Domain: expense_reimbursement
Selected actions: approveReport, disburseReimbursement

## Purpose

Determine whether a user may perform each of these operations: approve an expense report; disburse a reimbursement.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to approve an expense report
Action: approveReport
Requester type: User.
Resource type: ExpenseReport.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "LineManager" role; the user has the "FinanceReviewer" role].
- Access requires that the user's approval tier [principal.approvalTier] is one of [0; 1; 2].
- Access requires that the expense report's amount tier [resource.amountTier] is one of [0; 1; 2].
- Access requires that the expense report's lodging total [resource.lodgingTotal] is at least 0 USD cents.
- Access requires that the expense report's meal total [resource.mealTotal] is at least 0 USD cents.
- Access requires that the expense report's total amount [resource.totalAmount] is at least 0 USD cents.
- Unless all of [the request's emergency approval flag [context.emergencyApproval] is true; the user has the "FinanceReviewer" role], access requires that the user [principal] differs from the expense report's submitter [resource.submitter].
- Access requires that the user's approval tier [principal.approvalTier] is at least the expense report's amount tier [resource.amountTier].

## Permission to disburse a reimbursement
Action: disburseReimbursement
Requester type: User.
Resource type: Reimbursement.

Allow this action if and only if all the following requirements hold:

- Access requires that the user has the "Controller" role.
- Access requires that the reimbursement's amount [resource.amount] is at least 0 USD cents.
- If the reimbursement's amount [resource.amount] exceeds 500,000 USD cents, access requires that all of [the field "approver" is present on the reimbursement's report [resource.report]; the user [principal] differs from the reimbursement's report / approver [resource.report.approver]].
- Access requires that the field "approver" is present on the reimbursement's report [resource.report].
