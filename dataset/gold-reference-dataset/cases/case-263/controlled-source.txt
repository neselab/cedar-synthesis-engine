# Contract lifecycle authorization requirements

Case: case-263
Domain: contract_lifecycle
Selected actions: executeContract, reviewContract, signContract

## Purpose

Determine whether a user may perform each of these operations: execute a contract; review a contract; sign a contract.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to execute a contract
Action: executeContract
Requester type: User.
Resource type: Contract.

Allow this action if and only if all the following requirements hold:

- Access requires that the user has the "ContractAdmin" role.
- Access requires that the contract value [resource.contractValue] is at least 0 USD cents.
- Access requires that the contract's status [resource.status] equals the "signed" status [ContractStatusValue].
- If the contract value [resource.contractValue] exceeds 100,000,000 USD cents, access requires that the host confirms completion of the additional review [context.executeContractV8ReviewCompleted].
- Access requires that the request is on the corporate network [context.onCorpNetwork].

## Permission to review a contract
Action: reviewContract
Requester type: User.
Resource type: Contract.

Allow this action if and only if all the following requirements hold:

- Access requires that the user has the "Reviewer" role.
- Access requires that the contract value [resource.contractValue] is at least 0 USD cents.
- If the contract value [resource.contractValue] exceeds 1,000,000 USD cents, access requires that the user [principal] differs from the contract's drafter [resource.drafter].

## Permission to sign a contract
Action: signContract
Requester type: User.
Resource type: Contract.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "Signatory" role; the user has the "ContractAdmin" role].
- Access requires that the user's signing authority [principal.signingAuthority] is one of [0; 1; 2].
- Access requires that the contract value [resource.contractValue] is at least 0 USD cents.
- Access requires that the contract's required authority [resource.requiredAuthority] is one of [0; 1; 2].
- Access requires that the user [principal] differs from the contract's reviewer [resource.reviewer].
- Access requires that the user's signing authority [principal.signingAuthority] is at least the contract's required authority [resource.requiredAuthority].
- Access requires that the user has used multi-factor authentication [context.mfaUsed].
