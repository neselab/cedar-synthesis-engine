# Order refunds authorization requirements

Case: case-038
Domain: order_refunds
Selected actions: viewCardData

## Purpose

Determine whether a user may perform each of these operations: view an order's card data.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to view an order's card data
Action: viewCardData
Requester type: User.
Resource type: Order.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "ServiceRep" role; the user has the "Auditor" role].
- Access requires that the order's status [resource.status] differs from the "refunded" status [OrderStatusValue].
- Access requires that the order's contains card data flag [resource.containsCardData] is true.
- Access requires that the user has used multi-factor authentication [context.mfaUsed].
- Access requires that the user has the "Auditor" role.
- Access requires that the request's in cardholder zone flag [context.inCardholderZone] is true.
