# Folio adjustment authorization requirements

Case: case-010
Domain: folio_adjustment
Selected actions: approveAdjustment, postAdjustment

## Purpose

Determine whether a user may perform each of these operations: approve a folio adjustment; post a folio adjustment.
Each request names one user, one action, one resource, and trusted context supplied by the host application. Decide whether to allow that request using the current recorded facts.
The permissions do not perform state changes or assert an execution order between actions.

## How permissions apply

For each action, allow access if and only if the stated requester and resource types match and ALL requirements in that action section hold. Otherwise deny access. Deny requests for actions not listed here.
Each unless clause waives only the requirement in its own sentence. It never grants access or waives other requirements.
If a condition in an If sentence is false, only that sentence imposes no additional duty; every other requirement still applies.
Users may hold multiple roles. Role membership and ownership are distinct facts. Money is expressed in integer USD cents. Times are UTC. Daily time windows recur every day of the week.
Brackets identify exact fields or entity types. Role and status values identify entities of their declared types. True and false are Boolean values. Every listed interval includes only the endpoints explicitly stated.
Optional-field presence is explicit in the rules. A guarded predicate is false if a field it needs is missing; preserve the enclosing negation, condition, or waiver. Requirements about presence remain binding.
The separately supplied Cedar schema defines entity types, fields, optionality, action types, and valid enum vocabulary. Use that schema unchanged. Its declarations alone add no authorization requirements; declaring schedule fields does not impose a time window.

## Permission to approve a folio adjustment
Action: approveAdjustment
Requester type: User.
Resource type: Folio.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "AccountingClerk" role; the user has the "RevenueManager" role].
- Access requires that the folio's adjustment amount [resource.adjustmentAmount] is at least 0 USD cents.
- Access requires that the folio balance [resource.folioBalance] is at least 0 USD cents.
- Access requires that the folio's status [resource.status] equals the "adjustment_posted" status [FolioStatusValue].
- Access requires that the folio's property region [resource.propertyRegion] is the same hierarchy node as or descends from the user's assigned group [principal.assignedGroup].
- If the folio's adjustment amount [resource.adjustmentAmount] exceeds 10,000 USD cents, access requires that the large credit approval has been recorded [context.largeCreditApprovalRecorded].

## Permission to post a folio adjustment
Action: postAdjustment
Requester type: User.
Resource type: Folio.

Allow this action if and only if all the following requirements hold:

- Access requires that at least one of [the user has the "FrontDeskAgent" role; the user has the "NightAuditor" role].
- Access requires that the user's adjustment authority level [principal.adjustmentAuthorityLevel] is one of [0; 1; 2; 3].
- Access requires that the folio's adjustment amount [resource.adjustmentAmount] is at least 0 USD cents.
- Access requires that the folio's guest segment [resource.guestSegment] is one of [0; 1; 2; 3].
- Access requires that the folio's original charge [resource.originalCharge] is at least 0 USD cents.
- If the difference of [the folio's original charge [resource.originalCharge]; the folio's adjustment amount [resource.adjustmentAmount]] exceeds 250,000, access requires that the user's adjustment authority level [principal.adjustmentAuthorityLevel] is at least the folio's guest segment [resource.guestSegment].
- Access requires that the folio's dispute category [resource.disputeCategory] contains "billing_error".
